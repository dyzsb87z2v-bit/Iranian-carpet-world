# IRAN CARPET WORLD — نقشه اجرایی و معماری

> از هنر ایران تا خانه‌های جهان · From Iran's Heritage to Homes Around the World

این سند تحلیل کامل پروژه، معماری فنی، طرح دیتابیس، نقشه صفحات و برنامه فازبندی‌شده را مشخص می‌کند. هر جا «MVP» آمده، یعنی در نسخه فعلی کد ساخته شده است.

---

## ۱. تحلیل استراتژیک

### ارزش پیشنهادی
- **برای خریدار اروپایی:** دسترسی مستقیم به فرش اصیل ایرانی با اطلاعات شفاف (ابعاد، جنس، منطقه بافت، مدارک) و قیمت نهایی شفاف (کالا + ارسال + بیمه + گمرک + مالیات واردات).
- **برای فروشنده ایرانی:** بازار اروپا بدون نیاز به سایت، زبان خارجی یا پنل پیچیده؛ ثبت محصول با چند پیام تلگرامی.
- **مزیت رقابتی اصلی:** ربات تلگرام + هوش مصنوعی که عکس و چند جمله فارسی را به آگهی حرفه‌ای انگلیسی/آلمانی تبدیل می‌کند، با بازبینی انسانی قبل از انتشار.

### ریسک‌های کلیدی (به ترتیب اهمیت)
| ریسک | اثر | راهکار |
|---|---|---|
| تحریم‌ها و مسیر پرداخت | بدون مسیر قانونی، فروش ممکن نیست | پرداخت در کد **غیرفعال** است (feature flag). قبل از فعال‌سازی: مشاوره حقوقی تحریم در آلمان (BAFA / وکیل تجارت خارجی)، بررسی بانک و PSP. هیچ شرکت یا حساب واسطه صوری استفاده نمی‌شود. |
| صادرات فرش از ایران | ارسال واقعی | همکاری با ترخیص‌کار و حمل‌کننده معتبر؛ مسئولیت‌ها در قرارداد فروشنده مشخص شود. |
| اعتماد و اصالت | خرید گران‌قیمت آنلاین | تأیید دستی هر محصول، نشان «فروشنده تأییدشده»، مدارک اصالت، بعداً «شناسنامه دیجیتال فرش». |
| کیفیت تصویر | فرش بدون عکس خوب فروش نمی‌رود | راهنمای عکاسی در ربات، خدمات عکاسی به‌عنوان درآمد جانبی. |
| قوانین اتحادیه اروپا | GDPR، حق انصراف ۱۴روزه، DSA برای مارکت‌پلیس، Impressum آلمان | صفحات حقوقی، ثبت هویت فروشنده (KYB طبق DSA)، سیاست مرجوعی. |

### مدل درآمد
کمیسیون ۱۰–۱۵٪ (پیش‌فرض قابل‌تنظیم: ۱۲٪ در جدول `settings`)، سپس تبلیغات ویژه، خدمات عکاسی، کارشناسی اصالت و هماهنگی ارسال. مثال سند: ۳۰ فروش × ۲۰۰۰€ × ۱۲٪ = ۷٬۲۰۰€ درآمد ناخالص ماهانه.

## ۲. معماری فنی

```
                ┌──────────────────────────────────────────┐
  Buyers (EU) → │  Next.js 16 (App Router, TS, Tailwind 4)  │ ← Admin / Sellers (web)
                │  /[locale]  en · de · fa (RTL)             │
                │  Server Components + Server Actions        │
                │  /api/telegram/webhook  ← Telegram Bot API │ ← Sellers (Telegram)
                └───────┬──────────────────────┬────────────┘
                        │                      │
                ┌───────▼────────┐     ┌───────▼─────────┐
                │ Supabase        │     │ Claude API       │
                │ Postgres + RLS  │     │ استخراج مشخصات،   │
                │ Auth (نقش‌ها)   │     │ ترجمه EN/DE       │
                │ Storage (عکس)   │     └─────────────────┘
                └────────────────┘
```

**تصمیم‌ها و دلیل:**
- **Supabase** به‌جای Node جداگانه: Postgres واقعی، احراز هویت، Storage و Row Level Security در یک سرویس؛ سرور جدا لازم نیست. منطق کسب‌وکار در Server Actions و توابع SQL است.
- **ربات تلگرام به‌صورت Webhook داخل همان Next.js:** یک کدبیس، یک استقرار (Vercel یا هر هاست Node). وضعیت گفتگو در جدول `telegram_sessions` ذخیره می‌شود، پس serverless بودن مشکلی ندارد.
- **امنیت:** همه جداول RLS دارند. خریدار فقط محصولات `published` را می‌بیند؛ فروشنده فقط محصولات خودش؛ مدیر همه‌چیز. قیمت تومان در جدول جدای `product_private` است که خریدار هرگز به آن دسترسی ندارد. کلید `service_role` فقط سمت سرور (ربات و اکشن‌های مدیر).
- **حالت دمو:** اگر متغیرهای Supabase تنظیم نشده باشند، سایت با داده نمونه اجرا می‌شود تا طراحی و جریان‌ها قابل‌بررسی باشند.
- **پرداخت:** `CHECKOUT_ENABLED=false` به‌صورت پیش‌فرض. سبد خرید فقط «درخواست استعلام» ثبت می‌کند، نه سفارش تجاری.

### ساختار پوشه‌ها
```
src/
  app/[locale]/            صفحات چندزبانه
    page.tsx               خانه
    rugs/                  کاتالوگ + صفحه هر فرش
    seller/                پنل فروشنده
    admin/                 پنل مدیریت
    login/                 ورود
  app/api/telegram/webhook ربات تلگرام
  components/              اجزای UI
  i18n/                    پیکربندی next-intl
  lib/
    catalog.ts             لایه داده (Supabase یا دمو)
    landed-cost.ts         محاسبه قیمت نهایی (ارسال/بیمه/گمرک/مالیات)
    ai.ts                  استخراج مشخصات و ترجمه با Claude
    telegram/              ماشین حالت ربات
    supabase/              کلاینت‌ها
messages/                  ترجمه‌ها en.json de.json fa.json
supabase/migrations/       طرح دیتابیس و RLS
```

## ۳. طرح دیتابیس

| جدول | نقش |
|---|---|
| `profiles` | هر کاربر Supabase Auth؛ ستون `role`: `buyer` / `seller` / `admin` |
| `sellers` | فروشگاه: نام، شهر، تلفن، `telegram_chat_id`، وضعیت `pending/approved/rejected/suspended`، نشان تأیید |
| `categories` | دسته‌بندی با نام سه‌زبانه |
| `products` | مشخصات عمومی فرش: عنوان و توضیح سه‌زبانه، ابعاد، تار/پود/پرز، دستباف/ماشینی، شهر و منطقه، طرح، رنگ‌ها، تراکم گره، سن، وضعیت، موجودی، قیمت یورو، وضعیت انتشار `draft/pending_review/published/rejected/archived` |
| `product_private` | قیمت تومان و یادداشت داخلی (فقط فروشنده صاحب محصول و مدیر) |
| `product_media` | عکس و ویدئو، ترتیب نمایش |
| `product_reviews_log` | تاریخچه تأیید/رد توسط مدیر با دلیل |
| `ai_suggestions` | خروجی خام هوش مصنوعی + سطح اطمینان؛ هرگز مستقیم منتشر نمی‌شود |
| `favorites` | علاقه‌مندی خریدار |
| `inquiries` | درخواست خرید/استعلام (به‌جای سفارش، تا تأیید حقوقی) |
| `orders`, `order_items` | ساختار آماده برای آینده؛ ایجاد سفارش با flag قفل است |
| `settings` | نرخ ارز، کمیسیون، نرخ‌های تخمین گمرک/مالیات |
| `telegram_sessions` | وضعیت گفتگوی ربات برای هر chat |

فایل کامل: `supabase/migrations/0001_init.sql`.

### چرخه عمر محصول
```
draft ──(ارسال فروشنده/ربات)──► pending_review ──(مدیر تأیید)──► published
                                      │                              │
                                      └──(رد با دلیل)──► rejected     └──(غیرفعال)──► archived
```

## ۴. نقشه صفحات

**فروشگاه (عمومی):** خانه · کاتالوگ با فیلتر (قیمت، ابعاد، جنس، نوع بافت، شهر، کشور، وضعیت) · صفحه فرش (گالری، مشخصات، پلان ابعاد به مقیاس، فروشنده، تخمین قیمت نهایی برای کشور مقصد، دکمه استعلام) · صفحه فروشنده · علاقه‌مندی‌ها · سبد/استعلام · ورود و ثبت‌نام · صفحات حقوقی (Impressum، حریم خصوصی، شرایط).

**پنل فروشنده:** داشبورد (تعداد محصولات به تفکیک وضعیت) · محصولات من · افزودن/ویرایش محصول با قیمت تومان · پروفایل فروشگاه · استعلام‌های مشتریان · (بعداً) سفارش‌ها و کمیسیون.

**پنل مدیریت:** صف بازبینی محصولات (تأیید/رد + تعیین قیمت یورو) · مدیریت فروشندگان (تأیید/تعلیق) · دسته‌بندی‌ها · تنظیمات (نرخ ارز، کمیسیون، نرخ‌های گمرک) · استعلام‌ها · (بعداً) سفارش‌ها، گزارش‌ها، تبلیغات، اختلافات.

**ربات تلگرام:** `/start` ثبت‌نام فروشنده → ارسال عکس → سؤال‌های مرحله‌ای (نام، شهر، ابعاد، جنس، نوع بافت، سن، وضعیت، قیمت تومان) → هوش مصنوعی مرتب و ترجمه می‌کند → پیش‌نمایش برای فروشنده → ارسال به صف مدیر. دستورات: `/my` لیست محصولات، `/price` تغییر قیمت، `/stock` موجودی، `/off` غیرفعال‌کردن.

## ۵. محاسبه قیمت نهایی (Landed Cost)

برای خریدار به تفکیک نمایش داده می‌شود: **قیمت کالا + ارسال + بیمه + حقوق گمرکی + مالیات واردات (VAT کشور مقصد) + هزینه ترخیص**.
- ارسال: بر اساس وزن تخمینی (مساحت × چگالی نوع فرش) و تعرفه منطقه‌ای قابل‌تنظیم.
- بیمه: درصدی از ارزش کالا.
- گمرک: نرخ تعرفه فصل ۵۷ (فرش دستباف ۵۷۰۱) روی ارزش CIF — **نرخ پیش‌فرض باید توسط ترخیص‌کار تأیید شود.**
- VAT: آلمان ۱۹٪، فرانسه ۲۰٪، هلند ۲۱٪، اتریش ۲۰٪ روی (CIF + گمرک).
- مسئولیت پرداخت (DDP یا DAP) در هر محصول/سفارش قابل تعیین است.

همه اعداد «تخمین» برچسب دارند تا وقتی با شرکت حمل قرارداد بسته شود.

## ۶. هوش مصنوعی — قواعد

- ورودی: عکس(ها) + پاسخ‌های فروشنده. خروجی JSON ساختاریافته: عنوان پیشنهادی، توضیح EN/DE، دسته، فیلدهای ناقص و سؤال برای فروشنده، بازه قیمت تقریبی (فقط کمکی).
- **اصالت، قدمت، شهر بافت و جنس هرگز از روی عکس قطعی اعلام نمی‌شود**؛ هوش مصنوعی فقط «احتمال» می‌دهد، مقدار نهایی از فروشنده است و مدیر تأیید می‌کند.
- خروجی خام در `ai_suggestions` ذخیره می‌شود تا قابل حسابرسی باشد.

## ۸. راه‌اندازی محلی

```bash
npm install
cp .env.example .env.local   # بدون مقدار هم در حالت دمو اجرا می‌شود
npm run dev                  # http://localhost:3000/en
```

برای اتصال واقعی: پروژه Supabase بسازید، `supabase/migrations/0001_init.sql` را در SQL Editor اجرا کنید، کلیدها را در `.env.local` بگذارید. برای ربات: توکن از BotFather، سپس
`curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=<SITE>/api/telegram/webhook&secret_token=<TELEGRAM_WEBHOOK_SECRET>"`.
اولین مدیر: پس از ثبت‌نام، در SQL `update profiles set role='admin' where id='<uuid>';`
